Welcome to WISP Multitool

Your complete wireless ISP management platform.

What is WISP Multitool?

WISP Multitool is an all-in-one platform designed for wireless Internet service providers (WISPs) to manage every aspect of their operations:

  • Network Planning - PCI resolution, CBRS spectrum, coverage mapping
  • Field Operations - Mobile app for technicians, work orders, inventory
  • Customer Support - Help desk ticketing, subscriber management
  • Customers & Portal - Customer records, branded customer portal, billing, support tickets
  • Device Management - ACS/TR-069 CPE management, HSS subscriber auth
  • Team Management - Role-based access, user invitations, permissions
  • Wizards & Quick Tips - Guided wizards (site deployment, subscribers, RMA, onboarding) and in-module help

🔐 User Roles & Permissions

Understanding the role-based access control system.

Role Hierarchy

🏢 Platform Admin

Who: System administrator (admin@wisptools.io)

Access: ALL tenants, ALL modules, ALL permissions

Can: Manage all tenants, create owners, override any permission

👑 Owner

Who: Organization creator

Access: ALL modules in their tenant

Can: Manage users, configure modules, full administrative control

Cannot: Be changed or removed (permanent role)

⚙️ Admin

Who: Assistant administrators

Access: Configurable module access

Can: Manage users, configure permissions, access enabled modules

Cannot: Change owner role, delete organization

👷 Engineer

Who: Network engineers

Access: Technical modules only (PCI, CBRS, HSS, ACS, Distributed EPC)

Can: Configure network, manage subscribers, view all work orders

Cannot: Manage users, access help desk

🔧 Field Technician (Installer)

Who: Field workers

Access: Mobile app, assigned work orders, inventory checkout

Can: Deploy equipment, complete tickets, checkout inventory

Cannot: View other techs' tickets, configure network

🎧 Help Desk

Who: Customer support staff

Access: Help desk, work orders, ACS troubleshooting

Can: Create tickets, assign to techs, troubleshoot CPE

Cannot: Manage users, configure network

👁️ Viewer

Who: Read-only users, auditors

Access: View-only access to all modules

Can: View dashboards, reports, export data

Cannot: Make any changes

🔧 Troubleshooting

Common Issues

❌ Can't see a module on dashboard

Cause: Module not enabled for your role

Solution: Ask your administrator to enable the module in Settings → Module Access

❌ API calls fail with 403 Forbidden

Cause: Insufficient permissions for the action

Solution: Contact your administrator to update your role or permissions

❌ Mobile app not receiving notifications

Solutions:

  • Check app has notification permissions granted
  • Check user is logged in
  • Restart app to re-register FCM token
  • Check system notification settings

❌ Browser notifications not showing

Solution: Open the Notifications panel (bell icon on dashboard), click Enable notifications, and allow when the browser prompts. Notifications then appear for new unread items.

❌ Want to change light/dark theme

Solution: Click the Settings (gear) icon on the dashboard header and choose theme in the settings modal.

❌ Work order not appearing in mobile app

Cause: Work order not assigned to your user

Solution: Field technicians only see tickets assigned to them. Ask help desk to assign the ticket.

Getting Help

If you encounter issues:

  1. Check this documentation first
  2. Contact your organization administrator
  3. Check browser console for errors (F12)
  4. Clear browser cache and cookies
  5. Try logging out and back in

🗺️ Map Features

  • Color Coding: Cells colored by PCI conflict status
  • Click Cells: View detailed cell information
  • Right-Click: Add sites, edit sectors, delete sectors
  • Neighbor Lines: Shows cell adjacency relationships
  • Basemap Options: Streets, Satellite, Hybrid, Topographic

📐 Technical Details

PCI Conflict Rules:

  • Mod3 Conflict: PCIs with same value mod 3 (can cause confusion)
  • Mod6 Conflict: PCIs with same value mod 6 (can cause interference)
  • Direct Conflict: Identical PCIs within range (must be fixed)

Interference Range Calculation:

  • Based on cell height, azimuth, and distance
  • Typical range: 2-5 km for interference detection
  • Adjustable in analysis settings

🔧 Troubleshooting

No conflicts detected but cells are close:

Increase the interference range in analysis settings

Optimization changes too many PCIs:

Review AI recommendations first and apply selectively

Map not loading:

Check ArcGIS API key in environment variables

💡 Best Practices

  • Import all cell data before analysis
  • Review AI recommendations before auto-optimization
  • Export backup before applying PCI changes
  • Test PCI changes on small clusters first
  • Coordinate with network operations before deployment
  • Use Nokia export for quick configuration deployment

CBRS Basics

### What is CBRS? Citizens Broadband Radio Service (CBRS) is a 150 MHz wide broadcast radio frequency band in the United States (3550-3700 MHz). It operates under an innovative three-tiered spectrum sharing framework: 1. **Incumbent Access** - Federal and fixed satellite service users (highest priority) 2. **Priority Access License (PAL)** - Licensed users with protected spectrum 3. **General Authorized Access (GAA)** - Unlicensed users on available spectrum ### Spectrum Access System (SAS) The SAS is a cloud-based database and spectrum management system that: - Protects incumbent users from harmful interference - Manages spectrum assignments for PAL and GAA users - Provides dynamic spectrum allocation - Enforces FCC rules and regulations

Getting Started

### 1. Add a CBSD Device

Click "+ Add CBSD Device" and provide:

  • CBSD Serial Number - Unique device identifier
  • FCC ID - FCC equipment authorization identifier
  • Category - A (indoor, lower power) or B (outdoor, higher power)
  • SAS Provider - Google SAS or Federated Wireless
  • Installation Parameters:
    • Latitude and Longitude (decimal degrees)
    • Height above ground (meters)
    • Antenna gain (dBi)

Step 2: Register with SAS

Once added, devices must be registered with the selected SAS provider:

  1. Select device from the list
  2. Click "Register" button
  3. SAS validates device and installation parameters
  4. Upon success, device receives a CBSD ID

Step 3: Request Spectrum Grant

After registration, request a spectrum grant:

  1. Select registered device
  2. Click "Request New Grant"
  3. Specify:
    • Maximum EIRP (Effective Isotropic Radiated Power)
    • Frequency range (within 3550-3700 MHz)
  4. SAS evaluates request and assigns available spectrum

Step 4: Automated Heartbeat

Once granted, the system automatically:

  • Sends periodic heartbeats to SAS
  • Maintains spectrum authorization
  • Updates transmit expiration times
  • Reports device status

Device States

UNREGISTERED

Device is created but not yet registered with SAS. Cannot transmit.

REGISTERED

Device is registered with SAS and can request spectrum grants.

GRANTED

Device has one or more active spectrum grants but is not authorized to transmit.

AUTHORIZED

Device is authorized to transmit on granted frequencies. Active heartbeat required.

SUSPENDED

Spectrum grant is temporarily suspended. Cannot transmit until restored.

DEREGISTERED

Device is removed from SAS registration. All grants are terminated.

Grant Management

Requesting Grants

When requesting a grant, consider:

Frequency Range

  • Must be within CBRS band (3550-3700 MHz)
  • Typically 10-20 MHz channels
  • Avoid incumbent protection zones

Maximum EIRP

  • Category A: Up to 30 dBm/10MHz
  • Category B: Up to 47 dBm/10MHz
  • SAS may reduce based on interference analysis

Channel Type

  • PAL - Priority Access License (if you hold PAL)
  • GAA - General Authorized Access (most common)

Heartbeat Requirements

SAS requires periodic heartbeats (typically 60-240 seconds) to:

  • Confirm device operational status
  • Renew transmit authorization
  • Update interference measurements
  • Receive SAS commands

Heartbeat Process:

  1. System automatically sends heartbeats
  2. SAS responds with transmit authorization
  3. Authorization expires if heartbeat missed
  4. Device must stop transmitting if expired

Relinquishing Grants

Relinquish grants when:

  • Device is no longer transmitting
  • Spectrum is not needed
  • Preparing for deregistration
  • Changing frequency assignments

Compliance & Regulations

FCC Requirements

All CBSD operations must comply with FCC Part 96 rules:

  • Use certified CBSD equipment (FCC ID required)
  • Register all devices with SAS
  • Respond to SAS commands immediately
  • Maintain accurate installation records
  • Stop transmitting when required

Incumbent Protection

SAS automatically protects:

  • Federal radar systems (Navy shipboard radar)
  • Fixed Satellite Service (FSS) earth stations
  • Grandfathered Fixed Service operations

Protection Zones:

  • Coastal areas (0-80 km inland)
  • FSS earth station locations
  • Military installation perimeters

Record Keeping

Maintain records of:

  • Device registration details
  • Grant requests and approvals
  • Heartbeat logs
  • Suspension/termination events
  • Installation changes

🔧 Troubleshooting

Device Won't Register

Check:

  • FCC ID is valid and certified for CBRS
  • GPS coordinates are accurate
  • Device category matches equipment specs
  • No duplicate serial numbers
  • SAS API credentials are valid

Grant Request Denied

Possible Causes:

  • Requested frequency unavailable
  • Excessive interference predicted
  • In incumbent protection zone
  • Installation parameters invalid
  • Power level too high

Solutions:

  • Request different frequency range
  • Reduce max EIRP
  • Verify installation parameters
  • Check for nearby PAL holders
  • Contact SAS provider support

Heartbeat Failures

Check:

  • Network connectivity
  • SAS API endpoint accessibility
  • System clock synchronization
  • Certificate validity (if using SSL)
  • Grant expiration status

Actions:

  • Review error logs
  • Test network connection
  • Verify API credentials
  • Restart heartbeat service
  • Contact SAS support if persistent

Unexpected Suspension

Causes:

  • Incumbent activity detected
  • Interference reported
  • Missed heartbeats
  • SAS maintenance
  • Policy violation

Response:

  1. Immediately stop transmitting
  2. Check SAS messages
  3. Wait for AUTHORIZED state
  4. Resume only when cleared
  5. Investigate root cause

🔐 Authentication

How Authentication Works

The HSS generates authentication vectors for MMEs:

  1. MME requests authentication vector from HSS
  2. HSS generates RAND (random challenge)
  3. HSS calculates AUTN, XRES, CK, IK using Ki
  4. HSS sends authentication vector to MME
  5. MME challenges subscriber with RAND
  6. Subscriber calculates RES using Ki
  7. MME compares RES with XRES
  8. If match, subscriber is authenticated

Security Best Practices

  • Secure Ki Storage: Encrypt Ki values in database
  • Unique Ki: Each subscriber must have unique Ki
  • OP/OPc: Use operator variant keys for enhanced security
  • Regular Rotation: Consider rotating Ki periodically
  • Access Control: Limit who can view/edit Ki values

📚 Technical Details

IMSI Format

IMSI consists of:

  • MCC: Mobile Country Code (3 digits)
  • MNC: Mobile Network Code (2-3 digits)
  • MSIN: Mobile Subscriber Identification Number (9-10 digits)

Example: 310150123456789 (MCC: 310, MNC: 150, MSIN: 123456789)

Authentication Algorithms

  • MILENAGE: Standard 3GPP authentication algorithm
  • TUAK: Alternative authentication algorithm
  • Custom: Proprietary algorithms (not recommended)

APN Configuration

  • APN Name: Access Point Name identifier
  • IP Type: IPv4, IPv6, or both
  • QoS: Quality of Service profile
  • Charging: Charging characteristics
